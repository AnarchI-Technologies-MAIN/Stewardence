# Atlas report alignment before presentation changes

Atlas screen 38 is a partially implemented design reference. It supplies the
Reports continuity emblem, navy typography, blue information panels, white
surfaces, section hierarchy and progressive disclosure. It supplies no new
authority or financial facts. Screen 37 supplies report history rows; the
candidate uses immutable report identities and actual artifact metadata.

| Atlas concept | Existing context | Admission and presentation boundary |
| --- | --- | --- |
| Executive summary | executive_summary | Captured inventory count, rule findings, declared known spend and modeled value; unknown ROI remains unknown |
| Sources and methodology | methodology, evidence, ruleset_versions | Captured engine/rule versions and provenance; deterministic output does not prove the inputs true |
| Software costs | inventory, ai_expenditure | Declared known amounts and coverage; inventory defaults do not prove paid subscriptions |
| Insufficient ROI evidence | roi.result, roi.assumptions | AL-ROI-2 preserves required unknowns and known cost components; original AL-ROI-1 snapshots remain historical |
| Artifact availability | ReportArtifact and stored job status | Browser report is separate from a verified stored PDF; no renderer/worker health inferred from existence |
| Technical receipt | metadata | Immutable report/assessment/snapshot IDs and input/result digests; signatures and issuance authority are not inferred from hashes |

The atlas synthetic provider sidebar is not report data. Historical connection
failures, sandbox statuses, proposed integrations and collection promises are
not copied into reports. Current provider connection evidence cannot establish
permission inventories, financial payload admission or production readiness.

The scoped printable successor changes styling and the supplied decorative
Reports emblem only. It keeps the report context schema and deterministic
calculation engines intact and does not overwrite existing PDFs. Real Chromium
rendering, repeated-byte comparison, text checks and rendered-page inspection
must qualify the successor before release. Long tables and multi-page findings
require their own specimens; a single-page screenshot cannot qualify them.
